📄 Chunk Parameter Optimization

Why Reduce Chunk Size?

❌ Problems with 1500 tokens

  • Mixed with irrelevant content
  • Dense embedding signals diluted
  • High noise after BM25 hits
  • Not conducive to precise localization

✓ Advantages of 800 tokens

  • More concentrated information
  • Directly corresponds to original paragraphs
  • 200 overlap ensures continuity
  • Suitable for location-based retrieval

💡 Design Philosophy

Book QA is more like "location-based retrieval": expecting retrieval results to directly correspond to one sentence or a small paragraph from the original text, rather than a large mixed chunk.

💬 Prompt Rewrite: Suppress Hallucination

Core Design Principles

✅ Three Strict Rules

  1. Only use information from Context (prohibit external knowledge)
  2. Must explicitly state when information is insufficient
    "Based on the provided information, I cannot fully answer this question."
  3. Limit answer to 1-3 sentences (avoid excessive summarization)

Effect Comparison

Before Optimization ❌

  • Mixed with external knowledge
  • Fabricates when can't find answer
  • Over-summarizes into "short essays"

After Optimization ✓

  • Strictly cites original text
  • Explicitly states inability when can't answer
  • Concise and precise 1-3 sentence answers

📊 Evaluation System Improvement

Two Types of Test Sets

📝 Verbatim Questions

Answers are direct quotes from original text

Example: "What is stabilising process?" → Strict page number matching

📖 Summary Questions

Require summarizing multi-page content

Example: "Why did coffee trading fail?" → Page number ±1 window tolerance

Page Window Strategy

  • Verbatim: Only accept strict page ∈ gold_pages
  • Summary: Accept page ∈ [gold_page ± 1]
  • Rationale: Summary questions have information distributed across 2-3 pages, should not be marked as miss due to cross-page

Question Complexity Evolution

Level 1: Single fact → "When did he go to work?" Level 2: Single causation → "Why did he say X?" Level 3: Combinatorial → "Explain ancient history + real-time need + how delay breaks timing"
